# videolab — agent context

Tooling that turns a running app into a demo video. This repo is only the tool: it
holds no per-app content and tracks nothing about any project.

- **Record**: Playwright drives the real running app and saves footage.
- **Compose**: Remotion adds intro, outro, zooms, and captions to that footage.

The model writes and runs code. It never generates video pixels.

## Layout

```
bin/videolab.js                  CLI entry: list | record <video> | compose <video>
lib/                             recorder, composer, app/path helpers
studio/src/                      Remotion project: generic Demo composition
projects/                        scratch state, gitignored, deletable  (see below)
```

## projects/ — untracked scratch space

All per-video files are created here and are **never committed**:

```
projects/<app>/<video>/
  flow.js                        Playwright script (default export)
  video.json                     timing, zooms, captions (source of truth for the edit)
  raw/footage.webm               generated by record, disposable
  render/                        generated by compose (normalized MP4, props.json)
  out/<video>.mp4                generated by compose, the final video
  .snapshots/                    saved state zips (see "Snapshots" below)
```

`<app>` comes from the `name` field in the app's `demo.yml`. `.gitignore` excludes
`projects/` wholesale. It can be deleted at any time.

## Contract for agents working from an app repo

The app repo (the one with `demo.yml`) stays clean — videolab never writes into it.
Run the CLI from the app repo, never `cd` into videolab:

```
node <videolab>/bin/videolab.js list
node <videolab>/bin/videolab.js record <video>
node <videolab>/bin/videolab.js studio <video>
node <videolab>/bin/videolab.js compose <video>
```

To make a new video, copy an existing `projects/<app>/<video>/` folder and edit its
`flow.js` and `video.json`.

**May edit:** `projects/<app>/<video>/flow.js` and `projects/<app>/<video>/video.json`.

**Never edit:** `bin/`, `lib/`, `studio/`, another app's `projects/` folder, or any
`raw/`, `render/`, `out/` directory.

## Preview before composing

`studio` prepares `render/footage.mp4` and `render/props.json` and opens Remotion
Studio with the video's real footage and edit. It does not render:

```
node <videolab>/bin/videolab.js studio <video>
```

- The final video is produced only by `compose`. Do not render before the user has
  approved the preview.
- The command watches `video.json` and `raw/footage.webm`. Saving an edit rewrites
  `render/props.json`, and Studio picks it up live — no restart needed.
- `video.json` is the source of truth. The Studio props panel edits only the browser
  copy; translate requested changes into `video.json`.
- Port defaults to 3000 and falls back to the next free port. Tell the user the URL.
- The server runs from the videolab root, but invoke the command from the app repo.
- The command keeps running until stopped (Ctrl+C). Run it in the background so the
  agent can keep editing `video.json` while the user reviews.

## video.json

Times are seconds relative to the recording; `intro` and `outro` are seconds too.

- `title`, `subtitle`, `tagline`: intro and outro text.
- `fps` (default 30), `intro` (default 3), `outro` (default 4).
- `cursor` (default false): draw a pointer and click ripples in the recording. Read by
  `record`, not `compose`. Headless Chromium does not show the real mouse pointer.
- `zooms`: keys `{at, scale, originX?, originY?}`. `at` must strictly increase.
  `originX`/`originY` are percentages of the frame and set where the zoom focuses.
  Transitions ease in and out.
- `captions`: `{from, duration, text}`.
- `width`/`height` (optional): output window dimensions in pixels. Default to the
  recorded footage dimensions (no crop). Set them smaller than the footage (e.g.
  `720`×`1280` over a `1280`×`800` desktop recording) to render a vertical slice of
  a desktop page that pans/zooms within the footage.
- `captionStyle`, `introStyle`, `outroStyle` (optional): per-video style overrides
  merged over the component defaults. Keys include `background`, `color`, `fontFamily`,
  `fontSize`, `fontWeight`, `border`, `borderRadius`, `boxShadow`, `transform`,
  `padding` (caption); `background`, `titleColor`, `titleFontSize`, `subtitleColor`,
  `subtitleFontSize`, `fontWeight` (intro); `background`, `taglineColor`,
  `taglineFontSize`, `titleColor`, `titleFontSize`, `fontWeight` (outro).

## Recording pitfalls

- The app must not already respond at `demo.url`; videolab never kills servers it did
  not start.
- Dev servers that compile API functions on first hit (e.g. `vercel dev`) can stall the
  first real request. Warm those endpoints off-screen in `flow.js` via
  `page.request.get(...)`, which never touches the DOM and never appears in footage.
- Remotion occasionally times out on one frame (`delayRender`). Re-run `compose`.

## Snapshots — save and restore a video's state

A snapshot freezes the whole video folder into a zip so the user can undo a bad
iteration deterministically. Snapshots live in
`projects/<app>/<video>/.snapshots/` — plain zips plus a `manifest.json` that
records a label and optional comment for each. No git, no tooling.
They are never committed (already covered by the `projects/` rule) and are
ignored by `record`/`studio`/`compose`. Use these exact PowerShell commands;
do not improvise a different restore procedure.

### Save a snapshot

Run when the user says "take a snapshot", "I like this, save it", or similar.
`<short-label>` is a slug describing the state, e.g. `step5-baseline`. If the
user gives a comment ("this is the version with the new zooms"), record it in
`comment`; otherwise use an empty string. The zip plus the `manifest.json`
entry are what the user later reads to identify snapshots:

```powershell
$dir  = "<videolab>\projects\<app>\<video>"
$name = "{0:yyyy-MM-dd_HHmm}_{1}" -f (Get-Date), "<short-label>"
New-Item -ItemType Directory -Force -Path "$dir\.snapshots" | Out-Null
Get-ChildItem -LiteralPath $dir -Exclude ".snapshots" |
  Compress-Archive -DestinationPath "$dir\.snapshots\$name.zip" -Force
$manifest = "$dir\.snapshots\manifest.json"
if (Test-Path $manifest) { $all = @(Get-Content $manifest -Raw | ConvertFrom-Json) }
else { $all = @() }
$all += [pscustomobject]([ordered]@{
  name    = "$name.zip"
  savedAt = (Get-Date -Format o)
  comment = "<optional comment from the user>"
})
$all | ConvertTo-Json -Depth 4 | Set-Content $manifest -Encoding UTF8
```

Everything inside the video folder except `.snapshots/` is included — `flow.js`,
`video.json`, `raw/`, `render/`, `out/` — so a restore reproduces the exact
state, footage and rendered video included. Tell the user the snapshot name.

### List snapshots

Read `manifest.json` (it survives restores — restore never touches
`.snapshots/`). Fall back to plain listing if it is missing:

```powershell
$snaps = "<videolab>\projects\<app>\<video>\.snapshots"
if (Test-Path "$snaps\manifest.json") {
  Get-Content "$snaps\manifest.json" -Raw | ConvertFrom-Json |
    Select-Object name, savedAt, comment
} else {
  Get-ChildItem $snaps -Filter "*.zip" | Select-Object Name, LastWriteTime
}
```

### Restore a snapshot — DESTRUCTIVE, always confirm first

Restore replaces the entire video folder with the snapshot's contents. Always:

1. List the snapshots and ask the user to confirm the exact zip to restore.
2. (Recommended) Save a safety snapshot of the current state first, labeled
   `pre-restore`, using the Save recipe above.
3. Run the restore, then tell the user it is done.

```powershell
$dir = "<videolab>\projects\<app>\<video>"
$zip = "$dir\.snapshots\<timestamp>_<short-label>.zip"
$tmp = New-Item -ItemType Directory -Path (Join-Path $env:TEMP ([guid]::NewGuid().ToString()))
Expand-Archive -Path $zip -DestinationPath $tmp.FullName -Force
Get-ChildItem -LiteralPath $dir -Exclude ".snapshots" -Force |
  Remove-Item -Recurse -Force
Copy-Item (Join-Path $tmp.FullName "*") $dir -Recurse -Force
Remove-Item $tmp.FullName -Recurse -Force
```

The delete step (removing everything except `.snapshots/`) is essential: it
removes files created *after* the snapshot, which is what makes restore exact
instead of a merge. Restore is all-or-nothing — never restore individual files
"partially". After a restore, `raw/` and `render/` come back as they were, so
re-running `record`/`compose` is only needed to produce *new* footage or edits.

## Hard rules

- Never fake app behavior. Demo footage must come from the real UI. Zooms, captions,
  intro, and outro are fine; replaying one take as if it were several, or any
  simulated result, is not.
- Preview before composing: run `studio`, iterate on `video.json` until the user
  approves, and only then run `compose`.
- Nothing under `projects/` is ever committed, and no video, footage, or app-specific
  file belongs anywhere else in this repo.
- Do not write anything into the app repo.
- Do not install storylab/stickman tooling here.
- No shared `node_modules` between videolab and target apps.
